# 翻译示例与解码对照：实际结果

本轮只恢复翻译测评；其他语言实验、三组翻译训练继续暂停。没有训练新模型。

## 主要发现

1. 加示例总体有帮助：EN→SW贪心解码下，Base/LoRA/SSU的重复率分别从48.44%/85.16%/82.03%下降到33.59%/75.78%/67.19%。因此这批句子不支持“3-shot诱发更多重复”的方向。LoRA的chrF++改善仅+0.45，配对区间跨零，不能说仅加示例已可靠修复翻译。
2. 解码方式影响更大：固定3-shot，LoRA从贪心改为官方非思考采样，chrF++7.72→14.87，重复率75.78%→33.59%；SSU为8.77→15.12、67.19%→26.56%。对应chrF++差的探索性配对95%区间分别[+5.45,+9.07]、[+4.79,+8.04]。Base同条件chrF++15.03→15.71，变化区间跨零。
3. 采样3-shot下，LoRA/SSU相对Base的chrF++差为−0.84/−0.59，区间分别[−3.30,+1.46]、[−2.65,+1.42]。原先贪心下的大幅差距缩小，但这不是等效证明，更不是已取得正向翻译收益。重复仍约27%—34%，个别句子仍语义破碎。
4. 这支持“解码条件与微调后输出稳定性存在重要交互”这一工作解释；尚不能据此归因为训练噪声、排除能力损失或证明多任务梯度干扰。三组训练继续暂停，没有自动恢复。

## 设置

原始Qwen3-4B、原LoRA Final400、原SSU Final400；每方向128句FLORES dev，共3072次生成。新句组排除了此前64句开发材料和3条固定示例，但公开语料历史上已暴露，不称为全新盲测。每个模型复用同一引擎比较0-shot单轮与3-shot多轮；指令文字相同。

Greedy：temperature=0；官方非思考采样：temperature=0.7、top_p=0.8、top_k=20、min_p=0，seed42。均non-thinking、上限512tokens，EOS不变。此前正式翻译结果本来就是3-shot，不能把“加示例”描述成此前从未做过。

## 解释边界

这些对照能区分当前示例上下文与解码条件的影响，不能单独证明训练数据噪声导致退化，也不能证明多任务梯度干扰。若采样减轻重复但chrF++仍低，不能把正常终止当作翻译能力恢复。未将本轮开发结果替换到原1012句正式成绩表。

完整逐句输出与3条固定示例保存在本地保留的逐句案例文件（本次未重复发布）；示例题目在观察输出前按冻结顺序确定，不据此估计错误比例。
