# 知识选择题轮转补充诊断

这是一项对已冻结开发预测的事后分析，不启动模型推理，不改变原评分，不用于挑层、选模型或改正式任务协议。正式benchmark与开发探针仍分开。

## 两次轮转下是否稳定

每种语言有22个来源问题，每题两次选项轮转，共44行。以下“同一答案内容”依据候选答案文本规范化匹配，不是只看输出字母。

## 可以说什么

- SW两次都正确的问题由Base2/22变为FFT13/22、LoRA13/22、SSU10/22。与Base逐题比较，新增两次都正确分别为11、11、8题，没有丢失Base原本两次都正确的2题。
- Base在SW的44行中选A/B共40次，三种Final分别32、30、29次；分布依然不均衡，但所选答案内容在轮转后更稳定。
- 因此这批开发输入上的正确提升不只出现在某一次选项排列。然而，它可能包括语言理解、作答校准和已有知识调用的改变，**不能单独证明模型学到了新事实**，更不能定位模块或证明功能分离。

## 不能推广什么

这是事后描述，不是新的主要指标；只有22个固定来源问题、两个固定排列，并未覆盖所有排列。知识负例语义唯一性尚未独立复核，“同一内容”也不等于推理正确性。两次都正确的计数不是总体置信区间，不能替代正式Global-MMLU。完整114行汇总和2508行逐来源条件结果保留，未按有利方向筛选；对应的是3模型×19条件×2语言，以及每组22对，不是新增独立样本。

## 复算

```bash
python scripts/mechanism/audit_choice_rotations.py --probes /path/to/probes.jsonl --run full=/path/to/completed-full-run --run lora=/path/to/completed-lora-run --run ssu=/path/to/completed-ssu-run --output /path/to/new-rotation-audit
```

脚本不加载模型；要求原开发schema、冻结预测及DONE记录。检查每对候选内容集合和正确答案一致，重新映射候选内容并与原correct标记逐项比较。实际三组全条件复算退出码0：114汇总行、2508逐对行；原评分不变。
